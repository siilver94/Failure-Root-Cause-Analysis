# 2026-08-27 — NA-Global 중복 구조 발견, 모집단 재정의, 마스터 컬럼 확정

## 요약

전차축 파일럿 설계 중 데이터 구조에 대한 근본적 오해를 발견하고 수정했다.
기존에 "북미+글로벌 24,055건"으로 알고 있던 모집단이 실제로는 **동일 고장 사건의 이중 계상**을
포함하고 있었으며, 정정 후 **북미 전용 12,856건**으로 확정했다. 아울러 285개 컬럼을
43개로 선별하고 분자(고장) 정의를 확정했다.

## 결정 1: NA-Global 2단계 청구 구조 규명

### 발견 경위

`ClaimType__c='In Stock'`이 "판매 전 상태"라는 가설을 검증하던 중, 사용시간 이상치
(1,555h / 1,710h)를 조사하다가 **내용이 완전히 동일한데 CaseNumber만 다른 행이 쌍으로
반복되는 것**을 발견했다.

`AssetId + 고장일자 + CauseCode + DescriptionOfFailure`로 그룹화한 결과:

| 반복 횟수 | 그룹 수 | 행 수 |
|---|---|---|
| 1회 | 7,472 | 7,472 |
| **2회** | **8,233** | **16,466** |
| 3회 | 23 | 69 |
| 4회 | 12 | 48 |

2회 반복 그룹 8,233개 중 **8,219개(99.8%)가 (Global, North America) 조합**이었다.

### 구조 확정

연결키를 특정하여 검증:

- Global 레코드의 `OriginalClaimNumber__c` = NA 레코드의 `Id`
- **8,399건 100% 매칭** (15자리 정규화 기준)
- `IsFromNA__c` / `IsSentHQ__c`가 쌍 내부에서 100% 반대값
- `Account.Name`이 `TYM NORTH AMERICA (구 TYM USA)`인 Global 레코드 = 정확히 이 8,399건

```
딜러 → TYM-USA (North America 레코드)  →  본사 (Global 레코드)
```

### 업무 담당자 확인 사항 (데이터만으로는 알 수 없던 부분)

- NA에서 **시스템상 클레임 처리가 되지 않아** Global로 동일 건을 재클레임하는 구조
- 따라서 **완전한 데이터는 Global 레코드에 있음**
- NA 단독 건(재클레임 안 된 것) = NA에서 Rejected했거나, 재클레임 없이 직접 처리한 건
- Global 단독 건 = **북미가 아닌 타 국가 클레임** (초기에 "북미의 일부"로 잘못 가정했던 부분)

### Status 불일치의 의미

| (NA Status, Global Status) | 건수 |
|---|---|
| NA=Closed, Global=Rejected | 1,068 |
| **NA=Rejected, Global=Closed** | **0** |

거절은 본사 방향 단방향으로만 발생한다. 담당자 확인 결과:
**NA 서비스 담당자가 승인해 넘긴 건을 본사 글로벌 서비스팀이 최종 거절**하는 것.
`AdminNotes__c`에 "APPROVED BY MANAGEMENT"가 있으면서 `Status='Rejected'`인 케이스(936건,
그중 NA 5건)는 데이터 오류가 아니라 **1단계(NA) 판단 기록과 2단계(본사) 최종 판정이
순서대로 쌓인 것**이다.

→ **Status는 그대로 신뢰 가능. 재분류 로직 불필요.**

### 최종 정의

```

            = 12,856건

      (BAD BOY INC 1,578 / MCCORMICK 226 / WEBER 223 / RURAL KING 198 / INLON 109 등)

```

### Front Axle 결과의 안정성

기준을 3번 바꿨음에도 고장 현상 분포가 거의 변하지 않았다:

```
Leakage 47.4% + Oil Leakage 2.3% = 49.7%
Breakage 40.3%
→ 두 현상이 90%
```

상품기획팀 자료(전차축 파손 143 / 누유 89)와 Reddit·TractorByNet VOC(씰 누유, 서클립
파손 → 베어링 손상)가 독립적으로 동일한 두 현상을 지목한다. 3개 무관 소스가 일치.

## 결정 3: 분자(고장) 정의 확정

| 항목 | 결정 | 근거 |
|---|---|---|
| Status=Rejected | **포함** | 고장은 실재, 비용 판정만 거절 (구조적으로 증명됨) |
| ClaimType=In Stock (2,374→1,729) | **제외** | UsageTime 중앙값 1.4h. 고장일<판매일 76.7% + 판매일자 없음 14.8% = 91.5%가 판매 전 상태. 100h 초과 26건(1.5%)은 라벨 오류 |
| Damaged / Shortage / In House | **제외** | 물류·행정 이슈, 고장 아님 |
| Parts Warranty / Loader-Backhoe Warranty | 보류 | 추후 검토 |

In Stock은 제외하되 폐기하지 않는다 — "출고 품질(PDI 성격)" 별도 지표로 활용 가치가 있다.

## 결정 4: 마스터 컬럼 43개 선별

### 목표 변경

당초 "전차축 분석용"으로 컬럼을 고르려 했으나, **향후 모든 클레임 분석의 마스터 테이블**로
목표를 변경했다. 이에 따라 판단 기준도 변경:

| | 전차축 전용 | 마스터 테이블 |
|---|---|---|

| 애매한 컬럼 | 지금 안 쓰면 버림 | **나중에 쓸 수 있으면 남김** |
| 제거 기준 | 이번 분석에 불필요 | **어떤 분석에서도 무의미한 것만** |

`CauseCode__c`가 모든 부위(Engine, Front Axle, Electrical, Hydraulic 등 29종)를 담고 있어
`WHERE` 절만 바꾸면 다른 부위 분석에 그대로 재사용 가능하다.

## 결정 5: 신규 데이터 수신 요청

SFDC 담당자로부터 아래를 제공받기로 함 (어제자까지 최신 데이터 포함):

| 항목 | 기대 역할 |
|---|---|
| **Parts** (부품번호) | 귀책 구분(협력사 특정)의 열쇠. 분석 해상도를 부위 → 부품으로 |
| **Causal Code** | True=주원인(클레임당 1개) / False=부원인(N개). **True만 사용** |
| **Labor Code** | 작업 코드 |

수신 시 확인할 사항:
1. 별도 테이블(자식 객체)로 받는지, 조인 키는 무엇인지 → 평탄화되면 1행=1클레임 원칙이 깨짐
2. **부품번호 → 공급 협력사 매핑 마스터가 있는지** (귀책 구분의 핵심)
3. Causal=True가 클레임당 정확히 1개임이 시스템적으로 보장되는지
4. Labor Code / 부품번호 정의서 (코드만 받으면 `TM_Code__c`처럼 의미 불명이 됨)
5. 부분 승인 시 부품 라인별 승인/거절이 별도 기록되는지

추가 요청 가치가 있는 데이터:
- **기종별 보증 정책 표** — 보증 만료일 컬럼이 없어 "OUT OF WARRANTY" 거절을 검증할 수 없음
- **기종별 생산·판매 대수** — 고장률의 분모. 현재 분자만 있어 기종 간 비교 불가

예상 구조:
```
fra_master        (1행 = 1클레임, 12,856건)
      ↓ 1:N
부품 라인 테이블   (causal=True 필터 → 다시 1:1로 회귀)
```
