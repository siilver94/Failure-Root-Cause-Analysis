# 2026-09-22 — 원본 5단계 재검증, 부품-공급사 매칭 구조 문제 발견, PPT 파일 손상 원인 규명

## 1. "3,903건"의 정체 재검증 — 5단계 정제 과정으로 확장

### 배경
경영진 보고 PPT 1페이지("데이터 정비 과정")를 만들던 중, "원본 3,903건"이 정확히
어느 단계의 숫자인지 사용자가 질문. 원본 파일(`Warrnaty_Claim_Status2_csv_1.csv`,
157,414행)을 재업로드받아 처음부터 재검증함.

### 발견
기존에 "원본 단순집계 3,903건"이라 불러온 숫자는 **이미 Front Axle로 좁혀진 뒤**의
수치였다. 정확히는 "North America + Global 단순 합산(중복 미제거)" 상태에서
`CauseCode__c`='Front Axle'로 필터링한 값(NA 2,101 + Global 1,802 = 3,903).

진짜 0단계, 즉 **부위를 나누기 전의 전체 원본**은 3개 지역(한국/북미/글로벌) 혼재
고유 클레임 57,901건이었다.

### 확정된 5단계 정제 과정

```
0단계: 전체 원본(3개 지역 혼재, 고유 클레임)                57,901건
1단계: Front Axle 추출(북미+글로벌 단순합산, 중복 미제거)      3,903건
2단계: 북미 데이터 확정(NA-Global 중복 제거)                 2,103건
3단계: 필드 재검증(고장 정의 v4 적용)                       1,991건
4단계: 브랜드·계통 정리(Branson 제외, 최종 확정)             1,858건
```

### 시각화 시 주의점
0단계(57,901)와 1~4단계(3,903~1,858)는 스케일이 10배 이상 차이 나서 같은 막대차트에
넣으면 뒤의 4개 막대가 바닥에 뭉개져 안 보인다. 실제로 이 문제를 겪은 뒤 차트를
1~4단계만으로 분리하고, 0단계는 좌측 리스트에서 텍스트로만 크게 강조하는 방식으로 수정함.

## 2. 부품-공급사 매칭 — 생산용(1000/2000) vs 서비스용(1100/2100) 체계 상이 발견

### 배경
사용자가 기존 매핑 파일(`부품코드-공급사_매핑.xlsx`, 최종본, 12만행, 사이트 1100/2100)의
"보완 파일"이라며 신규 파일(`구매처2-Approved_vendor_list_by_products_.xlsx`, 96행,
사이트 1000/2000)을 제공.

### 검증 과정
두 파일을 단순 병합(union)하여 매칭률을 계산하니 **97.6% → 97.7%**까지 크게 상승.
새로 매칭된 부품들이 정확히 "미매칭 상위 6개"로 지목했던 부품들(와셔 16709510081 113건,
씰 13154130151 105건 등)이라 처음엔 개선으로 보였다.

그러나 사용자 확인 결과, 사이트 코드의 의미가 근본적으로 다름이 밝혀짐:
- **1000(익산)/2000(옥천)**: 생산 라인에 투입되는 부품(신차 조립용)
- **1100(익산)/2100(옥천)**: 서비스(A/S)로 나가는 부품(사후 교체용)

클레임의 원인 부품(`causal_parts_no`)은 "원래 고장난 부품"을 가리키므로, **생산
투입용(1000/2000) 기준이 정답**이다. 두 체계는 같은 부품이라도 공급사가 다를 수
있으므로, 단순 병합은 서로 다른 두 질문에 대한 답을 뒤섞는 오류였다.

### 정정된 결론
- 병합 매칭률 97.7%는 **폐기** — 잘못된 방식으로 계산된 착시 수치
- 생산용(1000/2000)만으로 단독 계산한 정직한 매칭률: **30.1%**
- 신규 파일(96행, 66개 품목)은 구매팀이 제공한 부분집합으로 추정되며, 생산투입
  전체 승인목록이 아닐 가능성이 높음
- 기존 "67.6%"(서비스용 1100/2100 exact match)도 재평가 필요 — 애초에 "원래
  고장난 부품이 어느 공급사에서 왔는가"라는 질문에는 목적이 안 맞는 기준이었음

### 조치
사용자가 구매팀에 생산투입(1000/2000) 전체 승인목록을 재요청함(진행 중, 결과 대기).
경영진 보고 PPT에는 검증되지 않은 숫자(67.6% 또는 97.7% 어느 쪽도)를 쓰지 않고,
"부품-공급사 매칭 추진 중 → 생산 투입분 기준으로 구매본부와 매칭 완성 예정"으로
숫자 없이 방향성만 기재.

### 일반화된 교훈
매핑/참조 파일에 "사이트 코드"나 "사업장 구분" 같은 필드가 있으면, 그 코드가
정확히 어떤 관리 체계를 가리키는지(생산 vs 서비스, 신차 vs 애프터마켓 등) 확인
없이 병합하면 안 된다. 매칭률이 갑자기 크게 개선되는 것처럼 보일 때는 특히
의심하고 재확인할 것 — 이번처럼 "우연히 딱 맞아떨어지는" 결과일수록 검증이 필요하다.

## 3. TYM 공식 PPT 템플릿 파일 손상 — 근본 원인 규명

### 증상
TYM 공식 템플릿(`template.pptx`)을 XML 직접 편집으로 재현해 경영진 보고 PPT를
제작하는 과정에서, 세 차례에 걸쳐 파일이 손상되는 문제가 반복 발생:
1차 - PowerPoint가 "복구" 절차를 요구
2차 - 복구 절차 없이 "읽을 수 없습니다" 오류로 아예 못 엶
모두 다음 검증 도구는 전부 통과한 상태였음: `validate.py`(스킬 제공 검증 스크립트),
python-pptx 재오픈, LibreOffice 렌더링, zip 무결성(`unzip -t`).

### 근본 원인
`docProps/app.xml`의 `<Slides>` 값과 `<TitlesOfParts>`(슬라이드 제목 목록)가 실제
슬라이드 구성과 불일치했음. 원본 템플릿은 8슬라이드였는데, 필요한 슬라이드만 남기고
2슬라이드로 줄이는 과정에서 이 메타데이터가 자동으로 갱신되지 않고 옛 값(`<Slides>4</Slides>`
또는 `<Slides>0</Slides>`, 8개 항목의 `TitlesOfParts`)이 그대로 남아있었음.

Windows PowerPoint는 파일을 열기 시작하는 초기 단계에 이 메타데이터를 엄격하게
검사하는 것으로 보이며, 불일치가 있으면 복구를 시도하거나 아예 열기를 거부한다.
반면 검증 스크립트·python-pptx·LibreOffice는 이 필드를 아예 참조하지 않기 때문에
문제를 계속 놓쳤다.

부수적으로 Content_Types.xml의 `<Default Extension="xlsx">` 중복 등록 문제도
동일하게 반복 발견됨 — 이것도 원본 템플릿 자체에 이미 존재하던 결함이었다.

### 해결책 — 매 패키징 직전 필수 5단계 검증
```
1. unzip -t 로 zip 무결성 확인
2. app.xml의 <Slides> 값을 실제 <p:sldId> 개수와 코드로 직접 대조·일치시킴
3. Content_Types.xml의 <Default Extension> 중복 등록 없는지 확인
4. python-pptx로 재오픈 테스트
5. LibreOffice로 PDF 렌더링해 시각 확인
```
이 5단계를 거친 이후로는 파일 손상이 재발하지 않았다. 특히 2번(app.xml 동기화)이
결정적이었다 — 이전에는 검증 도구가 다 통과해서 "괜찮다"고 판단했던 것 자체가
함정이었다는 점을 기억할 것.

## 4. 경영진 보고 PPT 방향 재수립

### "귀책" → "원인" 언어 전환
경영진이 이미 "네 탓 내 탓 하지 말고 다 같이 풀어라"는 방침을 밝힌 상황임을
확인. 이에 따라 문서 전반에서 "귀책/책임" 단어를 "원인" 중심 언어로 전면 교체.
품질본부 등 타 부서의 기존 수작업 분석을 직접 지적하지 않고, "방법론 표준화
부재"로 순화해 표현하는 원칙 재확인.

### 성격 재정의 — TF 구성 제안서가 아니라 데이터 분석 보고서
TF 구성 여부는 경영진이 판단할 사항이므로, 보고서 본문에서 "TF 구성 제안" 섹션을
제거. 대신 순수하게 "우리가 무엇을 확인했고, 이 데이터로 무엇이 가능한지"를
데이터와 시각화로 보여주는 보고서로 성격을 명확히 함.

### T5088 언급의 재해석
경영진이 인지 중인 전사적 품질 이슈(농민 클레임, 환불 사건 등)의 예시로 T5088이
언급되었으나, 확인 결과 T5088은 국내 전용(해외는 개발 중)이며 문제 자체는 특정
기종이 아니라 여러 기종에 걸친 전사적 이슈임을 확인. 전차축(Front Axle)은
"문제의 진앙"이 아니라 "이 방법론이 실제로 작동함을 증명하는 파일럿 사례"로
재포지셔닝.
